# 模块3项目介绍与模块4对接

本文是模块3“查询理解、混合检索与重排序”交付给模块4“答案生成与可信校验”的运行契约。模块4新代码应调用完整检索接口，不应只依赖旧的证据列表兼容函数。

## 1. 模块3项目介绍

模块3位于 `app/retrieval/`，只负责“理解用户问题并交付可回答、可引用的证据包”，不负责生成最终自然语言答案，也不直接实现前端页面。

主要能力包括：

- 查询分类，以及指标、期间、条款号、机构和银行档次等实体解析
- BM25、FAISS 向量检索和表格专用检索的统一编排
- RRF 候选融合与确定性业务重排序
- 年份、季度、月份、指标和适用档次的严格过滤
- 表格行级证据裁剪到具体单元格
- 证据来源完整性检查，以及澄清、拒答和故障降级判断
- 向模块4输出统一 `RetrievalResponse`

模块3相关目录边界：

```text
app/retrieval/                    # 查询理解、召回、融合、重排和证据选择
app/schemas/retrieval_schema.py   # 模块3与下游共享的响应结构
scripts/retrieve.py               # 模块3命令行运行入口
scripts/evaluate_module3.py       # 模块3离线检索评测入口
tests/test_module3_retrieval.py   # 模块3回归测试
```

模块3读取模块2交付的 `metadata.db`、FAISS 索引和 embedding 模型，不重新解析原始文件、不重新切分 chunk，也不在查询过程中重建索引。

## 2. 调用入口

```python
from app.retrieval.hybrid_retriever import retrieve

response = retrieve(question, top_k=5)
payload = response.to_dict()
```

默认读取：

```text
data/processed/kb_rebuild/metadata.db
indexes/kb_rebuild/
Model/bge-small-zh-v1.5/
```

`retrieve_evidence()` 仅供旧代码兼容。它只返回证据列表，会丢失 `status`、`module4_guidance` 和故障诊断；模块4正式对接不得仅使用该函数。

### 2.1 HTTP 检索接口（供任务4/任务5调用）

任务3同时提供一个只负责检索的 HTTP 接口。它不调用大模型、不生成最终答案，任务4/任务5可以在服务进程中调用：

```text
GET  /health
POST /api/v1/retrieve
```

请求示例：

```json
{
  "question": "2025年三季度商业银行资本充足率是多少？",
  "top_k": 5
}
```

启动：

```bat
uvicorn app.api.main:app --host 0.0.0.0 --port 8000
```

任务4/任务5应读取接口响应中的完整 `status`、`evidence`、`diagnostics` 和 `module4_guidance`；`/api/v1/retrieve` 的返回结构与 Python `retrieve().to_dict()` 保持一致。前端正式问答接口仍由任务5负责，不应让前端绕过任务4直接生成答案。

## 3. 模块4必须先判断状态

| 状态 | 模块4动作 |
|---|---|
| `answerable` | 可以基于证据生成答案，必须输出引用 |
| `degraded` | 可以生成答案，但要提示检索通道或重排序发生降级 |
| `needs_clarification` | 不生成答案，直接询问 `clarification_question` |
| `no_evidence` | 拒答或提示用户补充条件，不得猜测 |

建议逻辑：

```python
if not response.module4_guidance["may_generate_answer"]:
    return clarification_or_refusal(response.module4_guidance)
return generate_with_citations(response.evidence)
```

## 4. 完整响应结构

```json
{
  "query": "2025年三季度商业银行资本充足率是多少？",
  "status": "answerable",
  "analysis": {},
  "evidence": [],
  "diagnostics": {},
  "module4_guidance": {
    "action": "answer",
    "may_generate_answer": true,
    "require_citations": true,
    "preserve_numeric_source_value": true
  }
}
```

模块3会在检索前检查关键实体。例如“2025年三季度是多少”缺少指标，将直接返回 `needs_clarification`，避免模块4根据无目标召回结果猜测答案。

## 5. 表格数值处理边界

模块3会把行级表格证据裁剪到用户请求的具体期间单元格。例如查询“2025年三季度资本充足率”时：

```json
{
  "source": {
    "cell_ref": "D44"
  },
  "metadata": {
    "period": "2025Q3",
    "value": "0.15359",
    "value_numeric": "0.153590000000000000",
    "unit": "亿元、%",
    "table_cell_selection": {
      "original_cell_ref": "A44:E44",
      "selected_cell_ref": "D44",
      "value_preserved_as_source": true
    }
  }
}
```

模块3保留源数据原值，不把 `0.15359` 擅自改写为 `15.359%`。模块4如需百分比展示，必须结合指标语义和原表单位执行确定性换算，并同时保留原值与换算说明；不得直接输出 `0.15359%`。

模块1的行级 `values[]` 可能同时保留“指标名称单元格”和真正的数据单元格。模块3会忽略仅重复 `metric_name` / `row_header` 的标签单元格；如果请求期间只剩一个有效数据单元格，会将 `source.cell_ref` 裁剪到该单元格。

如果同一期间仍有多个有效数值列，而问题没有明确地区、险种、合计/分项等统计口径，模块3不会默认选择第一列，而是返回：

```json
{
  "status": "needs_clarification",
  "module4_guidance": {
    "action": "clarify",
    "may_generate_answer": false,
    "missing_entities": ["table_dimension"],
    "clarification_question": "同一期间匹配到多个数值列，请明确要查询的统计口径（财产险、人身险）。",
    "clarification_options": ["财产险", "人身险"]
  }
}
```

模块4应展示澄清问题和可选口径，不得自行选择某一列生成答案。

## 6. 引用要求

模块4引用条款证据时至少使用：

- `source.doc_id`
- `source.title`
- `source.clause_no` 或 `source.section_path`
- `source.source_url` 或 `source.local_path`

引用表格证据时至少使用：

- `source.doc_id`
- `source.title`
- `source.sheet_name`
- `source.table_name`
- `source.cell_ref`
- `metadata.metric_name`
- `metadata.period`
- `metadata.value` / `metadata.values`

若 `metadata.evidence_quality.complete=false`，模块4应降级提示或拒答，不应补造缺失来源。

## 7. 澄清示例

用户问：

```text
商业银行核心一级资本充足率最低要求是多少？
```

若当前候选只明确适用于第三档商业银行，模块3返回：

```json
{
  "status": "needs_clarification",
  "module4_guidance": {
    "action": "clarify",
    "may_generate_answer": false,
    "missing_entities": ["bank_tier"],
    "clarification_question": "请明确是第一档、第二档还是第三档商业银行。"
  }
}
```

模块4应原样或等价地发起澄清，不得直接把第三档的 `7.5%` 说成全部商业银行的统一要求。

反向边界同样成立：用户已经明确某一档商业银行时，候选证据必须明确包含同一档次。没有档次范围的通用条款、或标注为其他档次的条款，不能作为该问题的确定性答案；全部候选被过滤时返回 `no_evidence`。

## 8. 无证据与故障降级

- 指定年份/季度不存在时：`status=no_evidence`、`action=refuse`
- 某一检索通道失败但仍有可靠证据时：`status=degraded`、`action=answer_with_warning`
- `diagnostics.failures` 只提供组件和错误类型，不包含敏感配置
- 模块4不得因为向量相似度较高而越过 `may_generate_answer=false`

## 9. 模块4接入验收清单

- [ ] 使用 `retrieve()` 而不是只使用 `retrieve_evidence()`
- [ ] 先判断 `status` 和 `may_generate_answer`
- [ ] `needs_clarification` 时展示澄清问题
- [ ] `missing_entities=table_dimension` 时展示 `clarification_options`，不默认选列
- [ ] `no_evidence` 时拒答
- [ ] `degraded` 时显示风险提示
- [ ] 数字答案引用具体条款或单元格
- [ ] 百分比换算保留原值和换算说明
- [ ] 不修改或猜测证据来源字段

## 10. 模块4向 API 与前端的透传要求

模块3不直接修改前端。模块4生成答案、模块5封装 API 时，应将以下任务3状态和证据字段继续交给前端，不能统一压缩成“回答成功/回答失败”：

- `answerable`：展示答案和引用证据
- `degraded`：展示答案，同时显示检索降级风险提示
- `needs_clarification`：展示 `clarification_question`；存在 `clarification_options` 时提供口径选项，不生成答案
- `no_evidence`：展示可信拒答，不显示伪造答案
- 表格引用展示 `source.table_name`、`source.sheet_name`、`source.cell_ref`、`metadata.period` 和源数值
- 条款引用展示 `source.title`、`source.clause_no` / `source.section_path` 和来源路径

当前前端若仍通过 `retrieve_evidence()` 或只识别 `answered/refused`，只能作为旧兼容演示，尚未完成任务3完整状态接入。正式联调应由模块4/模块5调用 `retrieve()`，完成答案生成后保留上述状态和字段，再由前端负责展示。

## 11. 模块4接收与启动步骤

模块3代码通过 Git 交付，知识库、索引和模型权重通过共享盘压缩包交付。推荐顺序如下：

1. 模块4负责人先拉取包含模块3代码的最新 Git 提交。
2. 将共享运行资产解压到项目根目录，保持压缩包中的相对路径不变。
3. 在模块4自己的 Python 环境中执行 `pip install -r requirements.txt`；项目不要求模块4固定使用 Conda。
4. 先运行模块2基础混合检索，确认数据库、FAISS 索引和模型可用。
5. 再运行模块3完整检索，确认 `status`、证据和 `module4_guidance` 正常。
6. 模块4正式代码调用 `retrieve()`，不得只调用 `retrieve_evidence()`。

模块3在线运行真正需要的共享资产是：

```text
data/processed/kb_rebuild/metadata.db
indexes/kb_rebuild/faiss.index
indexes/kb_rebuild/chunk_id_map.json
indexes/kb_rebuild/vector_meta.json
Model/bge-small-zh-v1.5/
```

为了避免接收方逐个放置文件，可以制作一个保持上述目录结构的单一压缩包，例如：

```text
module3_runtime_assets/
├─ data/
│  └─ processed/
│     └─ kb_rebuild/
│        └─ metadata.db
├─ indexes/
│  └─ kb_rebuild/
│     ├─ faiss.index
│     ├─ chunk_id_map.json
│     └─ vector_meta.json
└─ Model/
   └─ bge-small-zh-v1.5/
```

接收方只需把压缩包内容覆盖到项目根目录。`embeddings.npy`、`bm25_corpus.jsonl`、`clause_chunks.jsonl` 和 `table_chunks.jsonl` 主要用于索引重建、审计或调试，在线检索不读取它们；若团队希望保留完整模块2产物，也可以将整个 `indexes/kb_rebuild/` 和 `data/processed/kb_rebuild/` 一并放入压缩包。

不建议直接发送整个 `data/` 目录作为常规交付，因为其中还包含原始附件、完整解析归档、测试样例及重复知识库目录，体积更大，并可能覆盖 Git 已跟踪的小型测试文件。若为了现场演示需要打开原始引用文件，可以额外发送 `data/raw/`，但它不是模块3检索和模块4答案生成的启动必需项。

接收后先执行：

```bat
python scripts/search_kb.py "资本充足率" --mode hybrid --top-k 5
python scripts/retrieve.py "2025年三季度商业银行资本充足率是多少？" --top-k 5
```

第二条命令应至少满足：

```text
status=answerable
source.cell_ref=D44
metadata.period=2025Q3
metadata.value=0.15359
module4_guidance.may_generate_answer=true
```
